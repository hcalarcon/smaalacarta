# SMA a la Carta

Antes de cambiar comportamiento, seguir [docs/WORKFLOW.md](docs/WORKFLOW.md):
requisito en [docs/SPEC.md](docs/SPEC.md) → test que falla → código → suite,
lint y build.

Ramas según [docs/BRANCHING.md](docs/BRANCHING.md): toda rama sale de
`development` y vuelve por pull request; nunca push directo a `main` ni a
`development`.

La documentación y los mensajes de commit van en español. Para el admin, ver
también `smaalacarta/admin/AGENTS.md`.
